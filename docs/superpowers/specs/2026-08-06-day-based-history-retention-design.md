# QuickPaste v0.22 按天数保留历史设计

## 背景与目标

QuickPaste 当前同时按普通历史数量、图片逻辑字节数和保留期限裁剪数据。普通历史默认最多 500 条，即使用户选择较长保留期限，也可能因为复制频率较高而提前失去仍在期限内的记录。

本版本把普通历史改为只按时间到期，不再按条数裁剪。图片仍保留独立的 256 MiB 逻辑容量保护，固定内容和永久片段继续免于自动清理。

成功标准：

- 期限内的普通记录不会因为总数超过 500 或其他任意条数而被删除。
- 普通记录只能选择保留 7、30 或 90 天，新安装默认 30 天。
- 固定内容和永久片段永不过期。
- 图片超过当前策略的逻辑容量时仍按既有规则优先清理最旧的未固定、非永久图片；新安装默认 256 MiB。
- 升级和恢复旧备份时，不会重新启用旧的数量上限，也不会静默删除旧版“永不过期”数据。

## 不在范围内

- 不新增自定义天数、云同步、数据库加密或磁盘配额服务。
- 不改变单条文本、HTML、RTF、图片和文件列表的既有安全上限。
- 不改变 SQLite 数据目录、剪贴板格式、搜索分页、OCR 或管理员粘贴协议。
- 不删除数据库和备份契约中的旧字段，从而避免不必要的破坏性 schema 迁移。

## 方案选择

采用“兼容字段保留、数量行为取消”的方案：

- `maxRecords` / `max_records` 继续存在于前端设置、IPC、SQLite 设置行和备份中，仅用于兼容旧版本。
- 规范值统一为 JavaScript 最大安全整数 `9_007_199_254_740_991`，表示当前版本不实施数量裁剪。
- 原生容量裁剪不再根据普通记录数量删除数据，避免旧设置或旧备份中的 `500` 意外重新生效。
- 不把 `maxRecords` 改成可空，也不删除列；这两种方式都需要扩大 SQLite、IPC 和备份迁移面，却不会改善用户行为。

## 保留规则

自动清理按以下顺序在同一数据库事务中执行：

1. 按所选期限删除到期的未固定、非永久记录。
2. 统计图片逻辑字节数；超过当前图片容量策略时，按复制时间和稳定 ID 顺序删除最旧的未固定、非永久图片，直到回到预算内或只剩受保护内容。新安装的容量策略为 256 MiB。
3. 不再统计或裁剪普通记录总数。

固定内容和永久片段在期限及图片容量裁剪中都保持既有保护语义。若受保护图片本身超过当前图片容量策略，应用报告实际占用，但不会静默删除用户保护的数据。

## 设置与升级兼容

设置 schema 提升到 v7，规则如下：

- 新设置和已有 7、30、90 天设置都把 `maxRecords` 规范为无限值。
- 新安装默认 30 天。
- 既有设置和旧备份中的图片容量保持原值，避免升级时因容量降低而静默删除图片；新安装默认 256 MiB。
- 设置页只提供 7、30、90 天，不再提供可重新选择的“永不过期”。
- 中英文界面删除“仍保留最近 500 条”等数量限制文案。
- 浏览器演示运行时与 Windows 原生运行时遵循同一条数无限规则。

旧设置或旧备份中的 `retentionDays = null` 作为“旧版永不过期”迁移状态处理：

- 首次升级或恢复后保留当前数据和 `null`，不得在历史加载前自动改成 30 天。
- 设置页显示不可重新选择的当前状态“旧版永不过期，请选择保留期限”，同时提供 7、30、90 天。
- 用户选择有限期限时，先计算将删除的普通记录数量，并沿用现有不可撤销操作确认框。
- 用户取消确认时继续保留旧策略和全部历史；确认成功后才事务性写入新期限并裁剪。
- 一旦改为有限期限，就不能从当前界面回到永不过期。

该迁移策略允许旧用户自行决定何时发生首次时间裁剪，避免版本升级或备份恢复造成静默数据丢失。

## 数据流与失败处理

应用启动时先严格解析本地设置，把任意旧 `maxRecords` 规范为无限值，再把策略同步到原生数据库。原生 mutation 和备份恢复入口都必须再次规范数量字段，不能信任前端已经迁移。

数量规范化与期限、图片容量裁剪在同一事务边界内完成。任何设置写入、删除或索引更新失败都整笔回滚，前端保留上一个已确认策略，并显示现有错误状态。读取历史失败时继续保持只读，不能通过迁移逻辑覆盖数据库。

恢复旧备份时：

- 忽略备份中较小的 `maxRecords` 行为，把结果规范为无限值。
- 保留备份中的图片容量，不因本次升级改变图片裁剪预算。
- 保留备份中的 7、30、90 天期限。
- 对 `null` 期限采用上述旧版迁移状态，不自动清理。
- 完成策略接纳、历史重载和统计刷新后再恢复捕获与 OCR 队列。

## 界面设计

设置页沿用现有“历史保留期限”行，不增加新卡片或复杂容量编辑器：

- 正常状态显示 7 天、30 天、90 天三个选项。
- 旧版迁移状态额外显示一个仅代表当前值的“旧版永不过期，请选择保留期限”选项。
- 辅助说明改为“普通历史按所选期限清理；固定内容和永久片段不会自动删除”。
- 改短期限或从旧版迁移状态选择期限时，继续显示预计删除条数并要求确认。

设置页和确认框必须覆盖紧凑窗口、浅色/深色主题、键盘操作及中文输入法组合态；不新增模态层级或独立导航。

## 测试策略

### TypeScript domain 与设置

- 默认策略使用无限数量、256 MiB 图片容量和 30 天期限。
- v6 及更早设置中的任意安全 `maxRecords` 都规范为无限值。
- 7、30、90 天正常往返；`null` 保留为旧版迁移状态。
- 浏览器演示历史超过 500 条后仍保留期限内记录。

### Vue 集成

- 设置页不再提供普通“永不过期”选项。
- 旧版 `null` 显示迁移状态，取消确认不改变策略，确认后才写入有限期限并移除到期项。
- 本地设置与原生 mutation 都收到无限数量规范值。
- 恢复旧备份后不会重新启用 500 条裁剪。
- 保留期限、焦点恢复、键盘交互和中文输入法组合态回归通过。

### Rust 原生层

- 插入超过 500 条且均在期限内的普通记录后全部保留。
- 到期的未固定、非永久记录仍被稳定裁剪。
- 固定内容和永久片段跨期限保留。
- 图片容量裁剪继续生效。
- 旧策略或旧备份携带较小 `max_records` 时不会触发数量删除，统计返回规范无限值。
- mutation、恢复及裁剪失败保持事务回滚。

### 发布验证

- 运行 `npm ci`、`npm run check` 和 `npm run build:windows`。
- 在真实页面检查设置页的浅色/深色、标准/紧凑窗口、键盘与中文输入法组合态。
- 核对 NSIS 候选数量、版本、大小、SHA-256、隐私扫描和第三方许可证。
- 未执行的真实机长循环继续标记为 `pending real-machine`，不以自动化替代。

## 版本与发布

该变更改变默认历史保留行为并移除用户可见选项，按项目规则提升 minor，目标版本为 `0.22.0`。

发布采用标准 GitHub Release，包含 Windows x64 NSIS 安装包和既有绿色版 ZIP。发布说明明确记录：

- 普通历史不再受 500 条限制，只按 7、30、90 天保留。
- 图片仍受既有容量策略保护，新安装默认 256 MiB。
- 固定内容和永久片段永不过期。
- 旧版永不过期用户需主动选择有限期限，升级不会静默删除历史。
- 真实机长期矩阵的未完成状态。
