# QuickPaste v0.24.0 验证报告

验证日期 2026-11-12，Windows x64 MSVC，Node 22.14.0、npm 11.9.0、Rust 1.89.0。

## 实施与审计

1. 先修复原生剪贴板写入、目标窗口和托盘。普通窗口以原顶层 HWND 和 PID 确认目标，子控件焦点尽力恢复，剪贴板序号变化只在读到不同内容时阻止自动粘贴。管理员 helper 仍校验授权、时限、焦点和剪贴板序号，启动前额外确认剪贴板载荷。前台跟踪使用进程外 WinEvent 通知。[Windows API 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook)
2. 补齐快捷面板空格预览、仅复制、删除、右键菜单、文件筛选、使用顺序和单击开关。链接、文件与图片动作继续通过既有的路径和格式校验。
3. 清除普通历史使用原生数据库事务。固定、集合内及永久记录均保留，图片、富文本和缩略图由现有外键级联处理。整理数据库会在 VACUUM 前后截断 WAL，按实际文件大小计算释放量。
4. 便携设置使用同目录原子替换。写入失败时保留 WebView 中待同步的设置，已有历史沿用 SQLite 已提交的保留策略。启动时先应用排除列表，再恢复记录。
5. 独立只读复审覆盖上述调用链。已修复剪贴板格式消失被误判为争用、旧便携设置覆盖较新设置、隐私初始化前捕获入队、菜单自身滚动关闭四项问题。主代理同时核对了管理员路径的写入和内容确认顺序。

## 自动化验证

- `npm ci`、`npm run check` 通过。47 项治理测试、34 个前端测试文件共 744 项、332 项 Rust 测试通过，另有 1 项共享系统剪贴板往返测试需显式运行。类型检查、Vite 构建、Rustfmt、Clippy、隐私和许可证检查通过。
- 系统剪贴板富文本往返已在同一原生实现上通过一次。最终重跑时，共享剪贴板无法完整备份，Win32 拒绝创建隔离窗口站。往返用例现要求空剪贴板和显式运行，避免自动测试覆盖用户剪贴板。
- Playwright 浏览器回归通过。640×440 与 390×620 覆盖浅深主题、空格预览开关、仅复制、删除撤销、文件筛选、模拟组合态、菜单定位和滚动、单击设置及来源排除。
- npm 生产依赖审计为 0 个漏洞。Rust 升级至 rusqlite 0.41.1、libsqlite3-sys 0.39.1、捆绑 SQLite 3.54.1 后，RustSec 漏洞项为 0，另有 17 个上游维护状态、yank 或 soundness 警告。Windows 的二维码依赖使用整数键缓存，调用链未使用 `LruCache::pop`。Tokio 的 `AsyncFd` 公告涉及 Unix API。[SQLite 安全公告](https://rustsec.org/advisories/RUSTSEC-2026-0459.html)

- 发布审计同时检查了开发依赖。已定向更新 Vite 8.1.6、Vitest 4.1.12、Happy DOM 21.0.4 和 brace-expansion 2.1.8。全量 npm 审计剩余 4 项中危，来自测试工具的 glob/minimatch 依赖链。生产依赖审计为 0，Windows 产物不包含该测试链。
